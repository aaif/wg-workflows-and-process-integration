## Summary

Reference Architectures delivered the working group's second voted artifact this month. "Single-Agent Process with Human Approval" passed unanimously at the 17 Sep plenary and is merged on main. The group voted on the current version and will track refinements as issues, rather than wait for a pending terminology cleanup (PR #50, since merged on 2 Oct). The second architecture, "bounded autonomous remediation", merged on the 29 August deadline and has been validated, but it hasn't gone to a vote yet and still has two open PRs against it. Critical Use Cases missed the 17 Sep vote date set at the 3 Sep plenary. The group agreed the inventory is observational rather than prescriptive, but wanted a terminology checkpoint across Use Cases, Reference Architectures, and Taxonomy before voting. A 22 Sep call with Reference Architectures then narrowed the vote to whether the inventory is useful as it stands, and agreed to replace "pattern" with "shape" throughout so it isn't confused with the patterns Reference Architectures recommends. On the Taxonomy side, one PR has been approved and a second one with 6 terms is under review in the cross-WG taxonomy stream. Taxonomy also confirmed "activity" as the term for a workflow subunit. There's still no agreed term for the business-level unit of work a workflow handles, so RA is using "business task" with a definition note for now (PR #50 merged that way, and PR #49 is still open).

## Blockers and Risks

- **Critical Use Cases' vote slipped past 17 Sep because of how the inventory might be read.** As of 22 Sep, three questions were in the way: whether the artifacts match the workstream charter, whether people would read the inventory as prescriptive, and what exactly the vote should cover. The word "pattern" made the second question harder. Use Cases used it for what it saw in deployments, while Reference Architectures uses it for recommended designs built from primitives. Both workstreams noticed the overlap on 8 Sep.
  - *Mitigation:* on the 22 Sep call, the vote was narrowed to whether the inventory is useful as it stands, the inventory was framed clearly as observational, and "pattern" is being replaced with "shape". RA expects to confirm this is resolved at the next WG meeting.
- **No agreed term for the business-level unit of work.** "Activity" covers workflow subunits, but nothing covers the request or problem that enters a workflow yet, and that gap held up the follow-up PRs #49 and #50 through September.
  - *Mitigation:* both PRs include a definition note for "business task" and merge as-is if Taxonomy has no better term, so they can't get stuck indefinitely. PR #50 merged that way on 2 Oct, and PR #49 is still open.
- **The second reference architecture doesn't have a vote date.** Bounded autonomous remediation is merged and validated, but PR #43 (minimum evidence) hasn't come together over two syncs since it opened on 4 Sep, and PR #49 is waiting on the term above.
  - *Mitigation:* Filip now owns turning the review feedback into one concrete revision, PR #49 can merge as-is the same way PR #50 did, and the single-agent vote showed we can vote with small items still open and fix them through issues afterward.
- **We haven't tested whether this is useful to practitioners.** The 24 Sep RA sync raised the question of whether this work is actually useful to practitioners, and at the 17 Sep plenary Jodee noted that the inventory will age quickly.
  - *Mitigation:* the RA sync suggested informally testing the material with practitioners outside the workstream. The inventory is also kept as a living document and is already getting new contributions (PR #51). Longer term, giving primitives, patterns, and architectures unique IDs could turn the catalog into a searchable knowledge base for tools, for example a wizard that compares a practitioner's design against the catalog and flags gaps. That idea is early and hasn't been acted on yet.
- **Dependencies across working groups, especially security and privacy.** At the 3 Sep plenary, Govindaraj raised that working groups are operating in silos, which affects deliverables and makes consistent messaging across the foundation harder. Govindaraj also passed on a request for a security and privacy cross-WG group, and pointed out that groups keep meeting notes in inconsistent ways.
  - *Mitigation:* Yaron supports the goal but wants cross-WG work to go through formal chair syncs rather than ad hoc participation. Yaron is also following up with Alex and Manik on consolidating meeting notes into a single source of truth in GitHub, possibly with an automated summary.
